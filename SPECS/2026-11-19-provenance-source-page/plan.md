### Banner wording (exact)

Every generated Markdown file starts with these four lines, then one blank line,
then the previous first line:

```
<!-- generated-file: do not edit by hand -->
> **Generated file. Do not edit by hand.**
> See the "Generated files" section of the repository README for the command
> that regenerates it.
```

The generated provenance TOMLs start with these three lines, then one blank line,
then `edition = "..."`:

```
# generated-file: do not edit by hand
# See the "Generated files" section of the repository README for the command
# that regenerates it.
```

The root README generated block starts with:

```
<!-- editions:begin -->
<!-- generated-block: do not edit by hand -->
> **Generated section. Do not edit by hand.**
> This block is produced by `python3 scripts/build_editions.py`; the rest of
> this README is hand-written.
```

Implementation rules:

- `markdown()` removes a leading banner it previously inserted (marker line
  followed by the blockquote lines and one blank line) before prepending, so
  `markdown(markdown(x)) == markdown(x)` and both HISTORY writers are
  idempotent. The body is not otherwise touched; no trailing newline is added.
- Banner lines contain no `=` and no relative links. The 17 generated files live
  at three different depths, so a relative README link would break somewhere;
  the prose pointer is depth-independent.
- `write_markdown()` is the only writer used for generated Markdown, so no call
  site can forget the banner.

**Why one shared helper and not per-writer strings.** There are a dozen writer
call sites across three packages and 17 files, one of them (`docs/HISTORY.md`)
has two writers, and the root README is partial. A per-writer string duplicates
wording, drifts, and would produce two different HISTORY banners depending on run
order. A fixed shared banner plus a registry-driven README table keeps the
wording, the test list, and the user-facing command list in one place. The
commands live in the registry, not in the banner, so a banner can never name a
stale command.
